# Linter coverage

Every file type tracked in this repository, and the hk steps (see `hk.pkl`)
that check it. The `lefthook-linter-coverage` step fails when a tracked type
is missing from this table, so a new file type cannot arrive unchecked. A `-`
in the Checks column is an exemption, and Notes gives the reason.

Every type is also covered by the hygiene steps, which run on all files:
trailing-whitespace, final-newline, line-endings, no-bom, no-merge-conflict,
no-case-conflict, no-broken-symlinks, no-private-key, ripsecrets,
no-large-files and typos.

This table is a bootstrap: once pkli can judge coverage itself, it replaces
the legacy checker and this file (T44).

| File type | Checks | Notes |
|-----------|--------|-------|
| `.rs` | rustfmt, clippy, test, rustdoc, coverage | Rust source |
| `.nix` | nixfmt | `flake.nix` |
| `.lock` | flake-lock-graph | `flake.lock`; `Cargo.lock` is generated by cargo |
| `.toml` | taplo | `Cargo.toml`, `clippy.toml`, `.typos.toml` |
| `.md` | mth-fmt, mth-check, sherd-check, sherd-nav, sherd-budget | the checks are for `SPEC.md`; other docs get the hygiene steps |
| `.pkl` | - | `hk.pkl` is evaluated against the vendored schema by every hk run, so a malformed one fails every hook; `pkl/Config.pkl` is vendored |
| `.envrc` | shellcheck | direnv entry |
| `.sh` | shellcheck | `scripts/` |
| `.yml` | actionlint, zizmor | `.github/workflows/` |
| `pre-commit`, `commit-msg`, `pre-push` | shellcheck | tracked hooks in `.githooks/` |
| `.gitignore` | - | git configuration; hygiene steps only |
| `.context-limits` | sherd-budget | read and validated by it |
| `.coverage` | coverage | read as the coverage floor |
| `LICENSE` | - | license text, nothing to lint |
| `.pklith` | - | pklith's own registry; `pkli check` parses it and fails on any error |
