# A measured example

What putting pklith into a real repository looks like, with the numbers it
produced. Everything here was run on 2026-09-27; the commands to reproduce
it are at the end. The repository is public:
[`nix-lefthook-unit-coverage`](https://github.com/pr0d1r2/nix-lefthook-unit-coverage),
at commit `0081084`, 19 tracked files of bash, bats, nix, YAML and
Markdown, gated until now by lefthook.

## From no gate to a gate

`pkli detect` read the tracked files and switched on eight fragments:
`base`, `actions`, `nix`, `shell`, `bats`, `markdown`, `yaml` and `spec`.

`pkli seed --init` wrote seven files: the hk gate (`hk.pkl`, an empty
`hk.pklith.pkl`, the vendored schema, `.githooks/pre-commit` and
`pre-push`), `.gitattributes`, and a first `.pklith`. It wrote no
`.editorconfig`, `.gitignore` or README, because the repository already had
them, and it did not claim them as its own.

The seeded registry gave each type the checks that reach it: `sh` got
`shellcheck` and `shfmt`, `nix` got `nixfmt`, `statix` and `deadnix`, the
workflows got `actionlint`, `zizmor` and `yamllint`, and every file got the
twelve universal checks. Five types got nothing, and the registry said so in
its header rather than guessing: `LICENSE`, `editorconfig`, `gitignore`,
`lock` and `nix-embedded-shell-allowlist`.

`pkli lay` then made **27 commits in 40 seconds**, one per check, each
through the repository's own hooks, cheapest first: whitespace and line
endings, then secrets, formatters, linters, and the spec checks last.

## The part a person decides

After lay, `pkli check` exited 1 naming the five types no check reads. That
is the design, not a failure of it: a file pklith cannot place is a
question for the repository's owner, and answering it takes one row each.

```text
LICENSE|-|-|licence text, nothing to lint
editorconfig|-|-|editor configuration, read by editorconfig-checker as config
gitignore|-|-|git configuration
lock|-|-|generated by nix flake lock
nix-embedded-shell-allowlist|-|-|a list of paths, read by the nix-no-embedded-shell check
```

With those rows `pkli check` passed, and the commit adding them went through
the twelve universal steps lay had just installed. `pkli confirm`
passed as well: every claimed check has a step, the generated files are
fresh, every tool is on `PATH`, and hk evaluates the gate.

## Against the tools it replaces

The legacy linter-coverage tools only checked that a file type was
*listed* in a Markdown table. Across nine repositories of the author's
fleet that carried such a table (some of them private), `pkli import`
turned each table into a registry, and `pkli check` against it reported
**the same gaps as the legacy tool in nine of nine**. It read the same 170
tokens the legacy awk read. The one difference was stricter, not looser:
rows naming a type no file has any more are reported as stale, which the
legacy tools could not see.

## Speed

Measured with `scripts/bench.sh --compare` on generated fixtures, best of
three, CPU milliseconds on an aarch64 Mac:

| | 50 files | 1,000 files | 10,000 files |
|---|---|---|---|
| `pkli detect` | 14 | 26 | 31 |
| legacy `detect-fragments.sh` | 79 | 120 | 152 |
| `pkli` as `lefthook-linter-coverage-full` | 4 | 5 | 15 |
| the legacy tool | 30 | 54 | 87 |
| `pkli check` | 1,883 | 2,656 | 4,067 |

`pkli check` has no legacy equivalent: it also evaluates `hk.pkl` with
`pkl`, which is most of its time, to prove every claimed check reaches its
files.

## What the numbers do not say

- Nothing here says the checks themselves are right for this repository.
  pklith makes the gate *complete* and *true to what it claims*; which
  linter a type deserves is still the owner's call, made in `.pklith`.
- The 40 seconds of `lay` are the repository's own hooks running 27 times.
  A heavier gate lays slower, once.
- This repository was small and conventional. The five exemptions are the
  honest cost of any repository whose files include things no linter reads.

## Reproducing this

```sh
git clone https://github.com/pr0d1r2/nix-lefthook-unit-coverage
cd nix-lefthook-unit-coverage
git checkout 0081084
nix develop github:pr0d1r2/pklith   # hk, pkl and the catalog's tools, as this run had
nix shell github:pr0d1r2/pklith     # pkli itself, inside that shell
pkli detect
pkli seed --init
git config core.hooksPath .githooks
git add -A && git commit -m 'ci: seed the gate' -m 'Seeded by pkli.'
pkli lay
pkli check      # names the five types above
pkli confirm
```
