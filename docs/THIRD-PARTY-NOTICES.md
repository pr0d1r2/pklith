# Third-party notices

`pklith` ships **1 direct dependency**, which pulls in 6 crates in
total. This file says what they are, why the direct one is there rather
than hand-rolled, and what licence the set carries.

## Why there is one at all

The project's own constraint is *do not add a dependency for something the
standard library already does*: the registry, TOML-subset, JSON and
Markdown readers are all hand-written. One dependency survived it:

| Crate | Why not hand-rolled |
|---|---|
| [`globset`](https://crates.io/crates/globset) | hk matches step globs with `globset` and fixed options (`SPEC.md` §R R19). pklith judges whether a claimed check reaches a file, so it must read a glob exactly as the runner does; a hand-rolled matcher would be a second reading of one rule. |

It has no network feature, and the build runs offline from the tracked
`Cargo.lock`.

## Not dependencies: the tools in the gate

These appear in the dev shell and the gate, and are **not** linked into
`pkli`. A consumer building the crate never sees them.

- [`hk`](https://github.com/jdx/hk): the gate runner, and the one whose
  steps pklith generates.
- [`pkl`](https://github.com/apple/pkl): evaluates `hk.pkl`; `pkli` calls
  it to read the effective hk configuration.
- [`microlith`](https://github.com/pr0d1r2/microlith) (`mth`): owns the
  `SPEC.md` format and checks it.
- [`sherd`](https://github.com/pr0d1r2/sherd): checks the federated spec
  and holds the coverage floor.
- [`itok`](https://github.com/pr0d1r2/itok): token counting for the
  per-file ceilings.
