# The `.pklith` registry

`.pklith`, at the repository root, is the one file you write. It says which
file types the repository has, which checks each type needs, and which
companion rules hold between files. `pkli gen` turns it into the hk steps in
`hk.pklith.pkl`; `pkli check` judges the repository against it. `pkli seed
--init` writes a first one from what your files switch on, and after that it
is yours: pkli never rewrites it.

The authority is [`src/registry/SPEC.md`](../src/registry/SPEC.md) and the
nodes it cites; this page is the reader's version.

## Shape

```text
format 1

# A comment line starts with `#`.

## types
type|checks|min|exempt
*|trailing-whitespace, typos|-|-
rs|rustfmt, clippy|-|-
lock|-|-|generated by cargo
```

- The first line is `format 1`. A newer number is refused by name, so an
  old `pkli` never misreads a registry written for a newer one.
- Each section is `## name` followed by its fixed header row, then one row
  per line. Sections are optional; an absent one is empty.
- Cells are separated by `|`. A literal pipe inside a cell is `\|`, and `-`
  means empty.
- List cells (`checks`, `glob`, `triggers`, …) are comma-separated.

## `## types`: what each file type needs

Header: `type|checks|min|exempt`.

**`type`**, the key a file is filed under:

| key | matches |
|---|---|
| `sh` | files ending `.sh` |
| `tar.gz` | a compound extension |
| `Makefile` | a bare basename |
| `.envrc` or `envrc` | a dotfile (the two spell one key) |
| `path:docs/**/*.md` | a path class: every file its glob matches |
| `*` | not a type: the universal checks, spread to every type |

A file resolves to the most specific `path:` class that matches it (longest
literal prefix, then order in the file). Otherwise it resolves to the first
of its basename's candidates that has a row: `foo.tar.gz` tries `foo.tar.gz`,
then `tar.gz`, then `gz`. Every tracked file lands in exactly one type; one
that lands in none is a **gap**.

**`checks`**: catalog ids, as many as the type needs. An unknown id is an
error naming its line.

**`min`**: how many checks beyond `*` the row must name; `-` means 1. The
universal checks never count toward it, because whitespace hygiene is not
coverage.

**`exempt`**: a reason the type needs no checks, or `-`. A row has checks
or an exemption reason, not both and not neither. An exempt type claims
nothing, not even `*`, and `pkli check` reports it apart, with its reason.

## `## checks`: your own checks, or the catalog's, changed

Header: `id|category|nix|glob|check|fix|env|msg`.

A row whose `id` matches a [built-in check](CATALOG.md) replaces it; a new
id adds one.

| column | meaning |
|---|---|
| `category` | `hygiene`, `secret`, `format`, `lint`, `spec`, `test`, `coverage`, `supply` or `gate`. `pkli lay` lays checks in that order, cheapest and broadest first. `coverage` checks run at push, the rest at commit. |
| `nix` | the nix attribute providing the binary, emitted into `nix/pklith.nix`; `-` for hk's own utilities |
| `glob` | the runner globs, emitted verbatim into the hk step |
| `check` | the command. `{{files}}` expands to the matched files. |
| `fix` | the command that repairs, or `-` |
| `env` | `KEY=value` pairs the step needs, comma-separated, or `-` |
| `msg` | what the failure means, printed when the step fails |

Every generated step first checks that its tool is on `PATH` and fails,
naming it, if not: a gate that cannot run has not passed.

## `## rules`: what must hold between files

Header: `id|kind|select|target|except`. `select` and `except` are glob
lists: the files the rule applies to, and those it leaves out.

| kind | holds when |
|---|---|
| `exists` | the rendered `target` path exists (every implementation has its test) |
| `mentions` | a file matching the target glob contains the rendered pattern; `target` is `<glob> :: <pattern>`, and the pattern is literal, never a regex |
| `changed` | the target changed whenever the source did; needs a diff, so it runs only under `pkli check --staged` or `--range A..B` |
| `orphan` | the reverse of `exists`: a target left behind with no source |

`target` is a template. Variables are `{path}`, `{dir}`, `{stem}` and `{ext}`,
each optionally followed by filters: `{stem|plural}`. Inside a cell the
filter pipe is written `\|`. Filters are `strip:<prefix>`, `chop:<suffix>`,
`suffix:<s>`, `ext:<e>`, `snake`, `dash` and `plural`. An unknown variable
or filter is an error when the registry is read, never an empty string. A
`//` left by an empty `{dir}` collapses.

```text
## rules
id|kind|select|target|except
paired|exists|src/**/*.rs|tests/{stem}.rs|src/main.rs
doc|exists|lib/*.rb|docs/{stem\|plural}.md|-
```

Rules are what `lefthook-unit-coverage`'s `mirror`, `flat`, `strip`,
`test_suffix`, `test_ext` and `normalize` become.

## `## plural`

Header: `singular|plural`. Irregular plurals for the `plural` filter, looked
up first; after that fixed suffix rules apply (`y` after a consonant becomes
`ies`; `s`, `x`, `z`, `ch`, `sh` take `es`; everything else takes `s`).
pklith never guesses with an inflector.

## `## fragments`

Header: `fragment|triggers|checks|seed`. A fragment is a bundle of checks
that files switch on: `triggers` are globs (or `always`), `checks` are
catalog ids, `seed` names the files `pkli seed` writes for it. The built-in
fragments are listed in [CATALOG.md](CATALOG.md); a row here with the same
name replaces one. `pkli detect` prints which are on.

## What `pkli check` reports

| finding | means |
|---|---|
| gap | a file type with no row |
| stale | a row no file resolves to |
| unbacked claim | a row names a check whose hk step does not reach one of its files, or is not in `hk.pkl` at all |
| failed rule | a rule a file breaks, naming the rule, the file and the missing target |
| unreflected fragment | files switch a fragment on and no row claims any of its checks; the rows `seed --init` would add are printed |

Exit codes: 0 when all is covered, 1 for findings, 2 for a registry or
command that could not be read. `pkli report` prints the same verdict as a
matrix, in text, JSON or Markdown.

## Coming from the legacy tools

`pkli import docs/linter-coverage.md > .pklith` turns a legacy linter
coverage document into a registry, every listed type exempt with its reason,
so the verdict carries over unchanged; a set-and-setting fragment map (the
JSON `nix eval --json` prints) imports the same way. Then replace the
exemptions with the checks that actually cover each type. See
[INTEGRATION.md](INTEGRATION.md) for the whole path, and [PORT.md](PORT.md)
for what moved from set-and-setting.
