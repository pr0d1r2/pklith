# Working in pklith

Notes for anyone, human or agent, changing this repository.

- Enter the dev shell first (`direnv allow`, or `nix develop`). Every tool
  the gate runs comes from it, pinned by `flake.lock`.
- Commits and pushes go through hk (`hk.pkl`) via the tracked hooks in
  `.githooks/`. The hooks refuse when hk is missing. Never use
  `--no-verify`: the gate refusing is the system working.
- Commit subjects are `type(scope): claim`, at most 72 characters, and the
  body says why. One change per commit.
- The design is a federated spec: `SPEC.md` at the root and one `SPEC.md`
  per node under `src/`. `§N` tables are generated by `sherd sync`; never
  edit them by hand.
- A step that fails prints what to do. If it names a missing tool, re-enter
  the dev shell; that is not a finding about your change.
